## 1. ひとことで言うと

**特別な瞬間や日常のエモい瞬間の「時間を止める」、安くて小さいデジタル多眼ウィグル・トイカメラ。**

横一列に並べた複数の小さなレンズで**同時にシャッターを切り**、撮れた数枚を **0.5〜1秒で素早く連続再生**することで、被写体は止まったまま視点だけが横にずれる映像(=**ウィグルグラム / wigglegram**)を生み出す。撮った数枚はスマホアプリへ送られ、自動で位置合わせ → ウィグル(GIF / 短尺動画)化 → SNSへ共有できる。

---

## 2. 体験シナリオ(誰が・どう使うか)

製品名「TimeStopper」が表すとおり、狙いは **“その瞬間の時間を止めて閉じ込める”** こと。

- **特別な瞬間を止める**: 誕生日ケーキを前にした主役のひと息、結婚式のウェディングドレス——普通の1枚写真ではなく、視点が横にスッと動く「動く写真」で記録する。
- **日常をエモく切り取る**: キーホルダー感覚で持ち歩き、「スタバに来た」程度の日常を、普通の写真ではなく多眼ウィグルで撮ると一気におしゃれ・エモくなる。
- 被写体は基本的に **ほぼ静止〜微動**(人・物・風景)。スポーツのような高速被写体は狙わない。

> この「ほぼ静止した被写体を前提にする」という割り切りが、後述のとおり同期の作り込みを軽くし、原価を下げる設計判断につながっている。

---

## 3. 着想の経緯

- 元ネタは映画『マトリックス』の**バレットタイム**(被写体を囲むように大量のカメラを円状に配置し、同時撮影 → 時間が止まったまま視点が一周する演出)。
- 「一周ぐるり」は装置が巨大になり、トイカメラにならない。そこで **発想をダウンスケール**:
  - カメラを**横一列に複数**並べる。
  - 一周ではなく**横方向に一瞬ずらす**動きに割り切る。
- これにより「マトリックス感」を、手のひらサイズ・低価格のトイで体験できるようにする。

## 4. 確定したコンセプト(第一弾モデル)

| 軸 | 決定 | 補足・狙い |
|---|---|---|
| 処理アーキテクチャ | **本体は「同期撮影」専用の安い端末**。位置合わせ・GIF/MP4化・共有は**スマホアプリ**に寄せる | 本体を最安・最小化。画面は原則不要(ステータス表示程度) |
| 転送方式 | **Wi-Fi**(本体がホットスポット、アプリが自動取得) | 帯域に余裕があり数枚を素早く転送可。ホットスポット切替のUXはアプリ側で吸収する設計とする |
| 本体ストレージ | **複数ためて後でまとめて同期**(内蔵フラッシュにバッファ) | スマホ非接続でも撮れる=「キーホルダー感覚で気軽に」が成立 |
| レンズ数 | **5眼を目標**。原価が厳しければ **4眼に縮退** | 縮退判断はBOM試算が出た時点のコスト閾値で決める |
| 被写体スコープ | **ほぼ静止〜微動**(特別な瞬間＋日常エモ写真)。高速被写体は非対象 | 同期要件を緩和でき、品質の肝はアプリ側のレジストレーションへ(§6) |
| 出力形式 | **GIF基本＋MP4書き出し** | GIF=「動く写真」のアイコン性、MP4=TikTok/Reels向け |
| 電源 | **内蔵LiPo＋USB-C充電** | Wi-Fiのピーク電流に耐え、ランニングコストゼロ(対フィルム) |
| アプリ | 本番=**iOS/Android クロスプラットフォームのネイティブ**／試作=**Webアプリ** | アプリ無しでは本体が使えないため両OS対応。試作は開発が速いWebで処理を検証 |
| メイン顧客 | **Z世代SNSユーザー** | 「エモ・かわいい雑貨」として動く写真を楽しむ層。Instagram/TikTok即投稿と好相性 |
| 価格 | **¥4,980〜7,980**(店頭目標) | RETO 3D(¥6,980)同等以下で「フィルム不要・デジタル即GIF」の価値訴求。BOM次第で薄利にならない範囲で更に下げたい |
| 形状(コアモデル) | **小型優先**(キーホルダー的・軽量) | ただしウィグルが死なない最低限のレンズ間隔(基線長)は確保 |
| 第一市場 | **日本** | 国内に同種の先行者がいない空白を先行で取る |

## 5. アーキテクチャと動作フロー

```
[本体] 横一列の小型カメラモジュール(複数)
   │  シャッター一押し → 全レンズを準同時に発火(§6)
   ▼
   数枚を取得(視差 = parallax) → 内蔵フラッシュにバッファ(複数ためられる)
   │
   │  Wi-Fi(本体ホットスポット)/ あとでまとめて
   ▼
[スマホアプリ] 自動取得
   ├─ 被写体を中心に各画像を位置合わせ(レジストレーション)  ← 品質の肝
   ├─ 高速に行き来再生してウィグル化
   ├─ 速度・中心・トリミング調整
   └─ GIF / MP4 書き出し → SNS共有
```

- **本体の責務**: 「複数レンズを準同時に撮る」「ためる」「Wi-Fiで渡す」だけ。安く・小さく保つ。
- **アプリの責務**: 重い処理(位置合わせ・ウィグル生成・書き出し・共有)を全部引き受ける。

## 6. なぜ「ガタつく」か / 品質の肝

ウィグルがきれいに見える条件は「**各コマがカメラ位置の違い(視差)だけで違っていて、それ以外は同じ**」こと。崩れる原因は2つ:

1. **同期ズレ(ハードの問題)** — レンズが完全な同時に切れないと、その合間に被写体が動いたぶんコマごとに被写体の位置・形が変わり、再生時に被写体が跳ねて見える。
   - **→ 本製品は被写体がほぼ静止している前提**なので、多少の同期ズレでは破綻しにくい。よって**超精密同期(高速被写体対応)は非要件**とし、原価を抑える。「普通の人やシーンが止まっているつもりの瞬間」で破綻しない**準同時発火**で足りる。
2. **位置合わせズレ(ソフトの問題)** — レンズは横にずれて並ぶため被写体が各コマで違う場所に写る。アプリが被写体中心にコマを揃える(レジストレーション)必要があり、これが甘いと被写体がフラフラする。被写体が動こうと止まっていようと**常に必要**。

> **結論: 品質の肝は「アプリ側のレジストレーション精度」**。ここに開発リソースを集中する。
> (この方針は OSS 調査の「静止〜ゆっくり被写体なら、準同時トリガ＋撮影後のソフト位置合わせで十分」という技術的知見とも一致。)

## 7. ハードウェア方針

- **構成**: 小型カメラモジュールを**横一列に複数(5眼目標／4眼フォールバック)**。シャッターで**準同時発火**。
- **電源**: 内蔵LiPo＋USB-C充電。
- **ストレージ**: 内蔵フラッシュにウィグル素材を複数バッファし、後でまとめてWi-Fi同期。
- **形状**: コアモデルは小型優先。ウィグルが成立する最低限の基線長は確保。
- **未確定(試作フェーズで決定)**: 採用するカメラモジュール／センサ／マイコン等の**具体的な部品・プラットフォームは未選定**。同期方式(準同時トリガで足りるか／クロック共有等まで要るか)も実機で実測して決める。

---

## 8. ソフトウェア(アプリ)方針

- **本番アプリ**: iOS/Android クロスプラットフォームのネイティブアプリ(1コードベースで両OS)。買った人を取りこぼさない。
- **試作アプリ**: 開発が速い**Webアプリ**で、肝であるレジストレーション→GIF/MP4化の処理パイプラインを先に検証する。
- **主要機能**: Wi-Fi自動取得 → レジストレーション → ウィグル生成(速度・中心・トリミング調整) → **GIF基本＋MP4書き出し** → SNS共有。
- **位置づけ**: アプリは「将来オプション」ではなく**製品の中核**(アプリ無しでは本体は使えない)。

## 9. モデル展開戦略

将来的に複数モデル展開を視野に入れる。

- **コアモデル(第一弾)**: 小型優先・キーホルダー的・Z世代向け・¥4,980〜7,980。本ドキュメントの主対象。
- **派生:強ウィグルモデル(後発)**: レンズ間隔(基線長)を広めに取り、動きを強調した大きめ筐体。**ガジェット好き／アーリーアダプター向け**。
- 派生として限定色・コラボなどの展開余地も想定。

## 10. 競合の中での立ち位置

- **デジタル × 多眼ウィグル × チープな単体トイ × 日本流通** を全部満たす製品は**現状存在しない**(＝狙う空白)。
- 最も近い K4MERA(多眼デジタルウィグル/スイス)は**高機能・高価格・未発売・日本未流通**で層が違う。
- 日本で意識すべきは RETO 3D(3眼フィルム・日本流通あり)とドンキ等の激安1眼トイデジ。いずれも「デジタルで動くウィグル」という体験では別物。
- → **差別化の核 = 「安い・小さい・撮ってすぐ動く写真・時間を止めるエモさ・日本で先行」**。
- 詳細は競合調査ドキュメント参照。

## 11. Go-to-Market(売り方)

- **クラファン先行(Makuake等)→ EC(Amazon.co.jp等)/雑貨店** の順で立ち上げる。
- クラファンで需要検証＋初期生産資金＋話題化(Z世代/アーリーアダプター)を行い、その後ECと雑貨店(Z世代動線)へ展開。
- 日本のクラウドファンディングにデジタル多眼ウィグルの先行者がいない(競合調査で確認)空白を取りに行く。

## 12. ロードマップ(大枠)

1. **試作**: ハード試作＋**Webアプリ**で品質の肝(レジストレーション→GIF/MP4)を検証。同期ズレを実機で実測。
2. **原価確定**: BOM/原価試算(部品単価・OEM有無)を行い、**5眼 or 4眼**と**最終価格**を確定。
3. **本番開発**: クロスプラットフォームのネイティブアプリ開発＋量産設計。
4. **ローンチ**: クラファン先行 → EC/雑貨店。

---

## 13. 残オープン論点 / 次アクション

- **BOM/原価試算**: 部品単価・完成品OEMの有無を確認し、(a)5眼か4眼か、(b)薄利にならない範囲での最終価格、を確定。
- **精密同期方式の技術評価**: 準同時トリガで品質が成立するか実機で実測。必要なら同期方式を検討(部品/プラットフォーム選定と一体)。
- **レジストレーション精度の検証**: 試作Webアプリで「ガタつかない」品質を出せるか。
- **Wi-Fi接続のUX設計**: ホットスポット切替の煩わしさをアプリでどう吸収するか。
- **特許の先行調査**: 同期・画像処理・装置構成について、販売前に弁理士による先行特許調査(競合調査§4参照)。

## 14. やらないこと(非ゴール)

- 一眼/ミラーレスに**装着するレンズ型**(本体が必要なやつ)。
- **フィルム式**(現像の手間・ランニングコスト)。
- 高機能・高価格の「写真愛好家向け」路線。
- **高速被写体(スポーツ等)**をピタッと止める用途(コアモデルでは狙わない)。
